## Session 3: Group Policy & Security Hardening

### Phase 4: Group Policy Basics (Completed)

**GPOs Created:**
- `POL-Domain-PasswordPolicy` - 14 char, complexity, no expiration (NIST), lockout 5/30min
- `POL-Domain-AuditPolicy` - Logon, account mgmt, policy change auditing (local to DC01)
- `POL-Workstations-Security` - Guest disabled, admin renamed to LabAdmin
- `POL-Workstations-Restrictions` - Screensaver 15min with password, control panel blocked
- `POL-Tier0-PAW-Lockdown` - Tier 0 logon only, USB disabled

**Key Learnings:**
- Password policy: NIST now recommends no forced expiration, no complexity (rely on length + MFA). Traditional settings still needed for compliance (PCI-DSS, HIPAA, etc.)
- Audit policy via GPO is complex - used `auditpol` for local config, GPO for enforcement
- SMBv1 and Windows Firewall already properly configured by default on modern OS (Server 2025, Win11)
- GPO troubleshooting: `gpresult /r`, `gpresult /h`, `gpupdate /force`

### Phase 5: Security Hardening (Completed)

**Microsoft Security Baselines Imported:**
- MSFT-Windows11-Security-Baseline → Workstations OU
- MSFT-Server2025-DC-Baseline → Domain Controllers OU
- MSFT-Server2025-MemberServer-Baseline → Servers OU
- MSFT-DefenderAV-Baseline → Domain root

**Additional Hardening GPOs:**
- `POL-Workstations-ASR` - 5 Attack Surface Reduction rules in audit mode
- `POL-Domain-CredentialProtection` - WDigest disabled, NTLM auditing, SMB signing/encryption required
- `POL-Domain-Logging` - 1GB security log, PowerShell script block logging, command line auditing

**Skipped/Deferred:**
- Credential Guard - requires nested virtualization (Proxmox VM limitation)
- Internet blocking on PAW - too restrictive for lab
- Admin logon restrictions - deferred to Phase 7 (Tiered Admin Model)
- ASR block mode - leave in audit until reviewed
