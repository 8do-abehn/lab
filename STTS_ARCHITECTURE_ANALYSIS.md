# STTS - Status Monitoring App Architecture Analysis

## Overview
**STTS** (Status This That Service) is a macOS status page monitoring application built in **Swift**. It monitors the status of various cloud services, showing their operational status in a menubar app with notifications.

- **Language**: Swift 5
- **Platform**: macOS
- **UI Framework**: Cocoa (NSView, NSViewController)
- **Build System**: Xcode
- **Package Manager**: Carthage + CocoaPods (Ruby scripts for generation)
- **Testing**: XCTest

### 1. Core Service Model

#### Base Service Protocol & Class Hierarchy

**File**: `/home/user/lab/stts/stts/Services/Super/Service.swift`

```
BaseService (parent class)
├── Implements: Loading protocol
├── Properties:
│   ├── statusDescription: ServiceStatusDescription (atomic)

│   └── lastNotifiedStatus: ServiceStatus

│   ├── all() - loads all services from services.plist
│   ├── updateStatus(callback:) - fetches current status (overridden by subclasses)
│   ├── _fail(_) - marks service as failed

│   └── (Comparable, Equatable, Hashable conformance)
└── Notification System: NSUserNotificationCenter
```

#### Service Status Enum

```swift
public enum ServiceStatus: Int, Comparable {
    case undetermined  // Error or loading
    case good          // All systems operational
    case notice        // Minor issue, usually informational
    case maintenance   // Scheduled maintenance
    case minor         // Minor outage
    case major         // Major outage
}
```

### 2. Service Definition & Discovery System

#### Service Registration via Plist

**Generated during build**: `services.plist` (generated by `/home/user/lab/stts/Scripts/generate_services_plist.sh`)

The plist file contains an array of all service class names:
```xml
<key>services</key>
<array>
    <string>Slack</string>
    <string>Stripe</string>
    <string>GitHub</string>
    <string>AWS (us-east-1)</string>
    ...
</array>
```

#### Service Discovery Process

```swift
// In BaseService.all()
BaseService.all() -> [BaseService]
    ├── Loads services.plist from Bundle
    ├── Reads the "services" array
    ├── For each service name, calls BaseService.named(name)
    └── Instantiates class via reflection:
        NSClassFromString("stts.\(name)") as? Service.Type
```

#### Persistence of Service Selection

**File**: `/home/user/lab/stts/stts/Preferences.swift`

Services selected by users are stored in `UserDefaults`:
```swift
var selectedServices: [BaseService] {
    get {
        guard let classNames = UserDefaults.standard.array(forKey: "selectedServices") as? [String] else {
            return []
        }
        return classNames.map(BaseService.named).compactMap { $0 }.sorted()
    }
    set {
        let classNames = newValue.map { "\(type(of: $0))" }
        UserDefaults.standard.set(classNames, forKey: "selectedServices")
    }
}
```

Default services: `["CircleCI", "Cloudflare", "GitHub", "NPM", "TravisCI"]`

### 3. Service Fetching & HTTP Layer

#### DataLoader - HTTP Client

**File**: `/home/user/lab/stts/stts/Services/Super/Service.swift` (contains Loading protocol)

```swift
class DataLoader {
    static let shared = DataLoader()  // Singleton
    private let session: URLSessionProtocol

URLSession.sharedWithoutCaching:
    ├── requestCachePolicy: .reloadIgnoringLocalCacheData
    └── urlCache: nil
```

#### Protocol-Based Design (for testability)

```swift
protocol Loading {
    func loadData(with urlRequest: URLRequest, completionHandler: @escaping URLSessionProtocol.CompletionHandler) -> URLSessionDataTask
    func loadData(with url: URL, completionHandler: @escaping URLSessionProtocol.CompletionHandler) -> URLSessionDataTask
}

protocol URLSessionProtocol {
    func dataTask(with url: URL, completionHandler: @escaping CompletionHandler) -> URLSessionDataTask
    func dataTask(with urlRequest: URLRequest, completionHandler: @escaping CompletionHandler) -> URLSessionDataTask
}
```

#### Service Data Fetching Pattern

All services use async completion-based fetching:

```swift
override func updateStatus(callback: @escaping (BaseService) -> Void) {
    loadData(with: url) { [weak self] data, _, error in
        guard let strongSelf = self else { return }
        defer { callback(strongSelf) }
        
        // Parse response and set statusDescription
    }
}
```

### 5. Status Fetching Implementations

#### StatusPage.io API Pattern

**File**: `/home/user/lab/stts/stts/Services/Super/StatusPageService.swift`

```swift
typealias StatusPageService = BaseStatusPageService & RequiredServiceProperties & RequiredStatusPageProperties

protocol RequiredStatusPageProperties {
    var statusPageID: String { get }
    var domain: String { get }  // Default: "statuspage.io"
}

// Fetches from: https://{statusPageID}.statuspage.io/api/v2/summary.json

class BaseStatusPageService: BaseService {
    override func updateStatus(callback:) {
        let summaryURL = URL(string: "https://\(realSelf.statusPageID).\(realSelf.domain)/api/v2/summary.json")!
        
        loadData(with: summaryURL) { data, _, error in
            // Decode JSON to Summary struct
            let summary = JSONDecoder().decode(Summary.self, from: data)
            
            // Parse status indicators and incidents
            let status = summary.status.indicator.serviceStatus
            let message = buildMessageFrom(incidents: summary.incidents)
            
            statusDescription = ServiceStatusDescription(status: status, message: message)
        }
    }
}

// Response Structure
struct Summary: Codable {
    let components: [Component]
    let incidents: [Incident]
    let status: Status
}

enum ComponentStatus: String, Codable {
    case operational
    case majorOutage = "major_outage"
    case degradedPerformance = "degraded_performance"
    case partialOutage = "partial_outage"
    case underMaintenance = "under_maintenance"
}
```

#### AWS Service Pattern

**File**: `/home/user/lab/stts/stts/Services/Super/AWSService.swift`

class BaseAWSService: BaseService {
    private static var store = AWSStore(
        url: URL(string: "https://health.aws.amazon.com/public/currentevents")!
    )

            callback(self)
        }
    }
}

#### HTML Parsing Services

**File**: `/home/user/lab/stts/stts/Services/Slack.swift`

Uses **Kanna** library for HTML parsing:

```swift
import Kanna

class Slack: Service {
    private enum SlackStatus: String {
        case check = "tablecheck.png"      // Good
        case outage = "tableoutage.png"    // Major
        case incident = "tableincident.png"  // Minor
        case maintenance = "tablemaintenance.png"
        case notice = "tablenotice.png"
    }
    
    override func updateStatus(callback:) {
        loadData(with: url) { data, _, error in
            let doc = try? HTML(html: data, encoding: .utf8)
            let serviceImages = doc.css("#services .service.header img")
            let statuses = serviceImages.compactMap { img in
                let filename = (img["src"]?.lowercased() as NSString).lastPathComponent
                return SlackStatus(rawValue: filename)
            }
        }
    }
}
```

#### JSON API Services

**File**: `/home/user/lab/stts/stts/Services/Stripe.swift`

```swift
class Stripe: Service {
    let url = URL(string: "https://status.stripe.com")!
    
    override func updateStatus(callback:) {
        loadData(with: url.appendingPathComponent("current/full")) { data, _, error in
            let currentStatus = try JSONDecoder().decode(StripeCurrentStatus.self, from: data)
            
            statusDescription = ServiceStatusDescription(
                status: currentStatus.uptimeStatus.serviceStatus,
                message: currentStatus.message
            )
        }
    }
}

private struct StripeCurrentStatus: Codable {
    enum Status: String, Codable {
        case up, degraded, down, pending, paused
        
        var serviceStatus: ServiceStatus {
            switch self {
            case .up: return .good
            case .degraded: return .minor
            case .down: return .major
            default: return .maintenance
            }
        }
    }
    
    let message: String
    let uptimeStatus: Status
}
```

### 9. Notification System

**File**: `/home/user/lab/stts/stts/Services/Super/Service.swift`

```swift
func notifyIfNecessary() {
    let notifyBecauseDifferent = 
        lastNotifiedStatus != nil 
        && lastNotifiedStatus != status
        && Preferences.shared.notifyOnStatusChange
    
    if notifyBecauseDifferent {
        let notification = NSUserNotification()
        notification.title = "\(name)'s status has changed"
        notification.informativeText = message
        NSUserNotificationCenter.default.deliver(notification)
    }
    
    lastNotifiedStatus = status
}
```

## Summary: How Monitoring Works

1. **Service Discovery**: Services are registered by class names in `services.plist`
2. **User Selection**: Users select which services to monitor (stored in UserDefaults)
3. **Periodic Updates**: Timer fires every 5 minutes, triggering status updates
4. **Async Fetching**: Each service's `updateStatus()` fetches data from its API/status page
5. **Parsing**: Services parse responses based on their specific format (JSON, HTML, etc.)
6. **Status Mapping**: Responses are mapped to `ServiceStatus` enum values
7. **Storage**: Current status stored atomically in each service instance
8. **Notifications**: If status changes, user is notified
9. **UI Update**: Menubar and table view updated with latest statuses

## Web Application Conversion Considerations

Key architectural points for converting to a web application:

1. **Service Model** - Remains mostly the same; can be ported to any language
2. **HTTP Layer** - Replace URLSession with web framework's HTTP client
3. **Data Persistence** - Replace UserDefaults with database/localStorage
4. **Periodic Updates** - Replace NSTimer with backend scheduler/cron or websockets
5. **Notifications** - Replace NSUserNotificationCenter with web push notifications
6. **Service Discovery** - Keep the registry pattern (plist → database/config file)
7. **Status Fetching** - Core logic is independent of platform
8. **UI** - Complete redesign for web (React, Vue, etc.)
9. **Preferences** - Move to user account/settings database
10. **Generated Services** - Keep generation scripts, may need adaptation for data format
